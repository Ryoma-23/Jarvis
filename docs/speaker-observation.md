# 本人の声の登録と観測用話者照合（v1.50）

## 今回の範囲

本人の声をローカル登録し、会話音声との類似度を観測します。
起動語・応答・割り込みの許可／拒否には使用しません。会話が他の声に反応する現象は、
まだ止まりません。文字起こしモデル・言語・VAD・既存の会話条件は維持しています。

## ユーザーの作業：初回登録（5〜10分）

1. Tray、Window、バックエンドを完全終了してJarvisを再起動します。
2. 音声会話を切断します。動画や他の音声を止め、普段のマイク・位置で準備します。
3. 右上の「本人の声の登録・照合」を開き、「新しい登録を作る」を押します。
4. 例文を選び「録音開始」。「録音中」の表示が出てから読み上げます。
5. 自然な声で読み、「停止して保存」を押します。12秒で自動保存されます。
   最低2秒の一定以上の音量の区間が必要です。例文1本で4〜10秒を想定しています。
   短すぎる、小さすぎる、音割れする音声は理由を表示し、登録しません。
6. 異なる例文を8本以上登録します。可能なら10本読み、小さめの声の例文も含めます。
   他人の声が混ざった音声を本人の声として登録しないでください。
7. 「この登録を使用（8本以上）」を押し、「使用中」の表示を確認します。

登録中はWebRTC接続・Realtimeトークン取得を行わず、OpenAIへ音声を送りません。
Trayの既存マイク受け渡しでWake Word側のマイクを止め、終了・中止・失敗時に解放します。
解放失敗時は「中止／マイク解放」で再試行してください。
OSのマイク許可操作が必要な場合は、ユーザーが行ってください。

## ユーザーの作業：比較測定（10〜15分）

1. 「会話中の話者照合を観測する」をオンにします。Window再起動後はオフです。
2. 「音声診断」を開き「診断開始」。本文の診断ログへの保存は引き続き任意です。
3. 通常どおり音声会話を接続し、照合を観測中の表示を確認します。
4. 発話前に毎回「次の試行」を押し、以下を試します。登録とは別の文を使います。

| 条件 | 内容 |
| --- | --- |
| 静かな環境 | 「元気？」「ありがとう」「今日の曜日を教えて」「雨の日の過ごし方を二つ教えて」を各2回 |
| 動画だけ | 別端末の普段誤反応する動画を1試行60秒×3回。本人は話さない |
| 動画＋本人 | 同じ音量・マイク位置で、上の4発話を各2回 |
| 割り込み | Jarvisが話す途中に「ジャービス、止めて」を別々に3回 |

5. 発話ごとに「正しく応答した／拾わなかった／他の音に反応した／不明」を付けます。
   前の試行への印付けは「結果を付ける試行番号」を選び直してください。
   「動画だけ」を選んだまま本人が話さないよう、条件を先に確認します。
6. 最後の照合結果が表示されてから診断を終了し、保存ファイル名を伝えてください。
   未完了の照合は診断終了後には記録されません。

短い発話が「材料不足」でも会話は従来どおり進みます。
結果の印は応答に対して付けます。話者の正解ラベルとは別なので、重なった発話は条件を明示します。

## 仮判定の意味

- `owner_candidate`：本人候補（コサイン類似度0.60以上）
- `other_candidate`：別話者候補（0.35未満）
- `uncertain`：判定保留
- `insufficient`：音声材料不足または音割れ
- `skipped_busy`：前の照合が処理中のためスキップ
- `capture_unavailable`：音声区間の取得不能（開始前／長すぎる区間等）

0.60／0.35は未校正の探索用区分で、本人である確率ではありません。
日本語・本人・この環境での精度は測定後に評価します。エネルギーによる品質チェックは
声と動画・音楽を区別しません。本人の録音再生、似た声、同時発話、スピーカーの回り込みを
確実に区別できるものではありません。

## 処理と測定上の制限

会話用マイクの同じMediaStreamをAudioWorkletで観測します。追加のマイクは開きません。
観測グラフの出力は無音で、会話用トラックを停止・ミュートしません。
音声はメモリーの約22秒リングバッファに保持し、オフ・切断で破棄します。
発話開始通知受信の0.8秒前から終了通知受信までを比較するため、サーバーとの厳密な時刻同期ではありません。
通信遅延、直前の別話者、末尾の無音、Jarvisの声が混ざる場合があります。
15秒を超える区間は無理に対応付けずスキップします。

WAVはlocalhostへ送り、16kHzに変換して特徴を抽出します。
登録の正規化特徴の平均とコサイン類似度を計算します。同時推論は1件までで、
バックエンドの別スレッドで処理します。無制限に待ち行列へ音声を蓄積しません。
`compute_ms`は品質チェック・初回モデルロードを含むサーバー処理時間、
`roundtrip_ms`は比較リクエストから完了までです。発話を待つ時間・VAD待ちは別です。
この段階は発話終了後の観測で、低遅延の途中判定を有効にする実装ではありません。

開発時の合成入力では、モデル読込約148ms、3秒入力の特徴抽出約45msでした。
人間の音声精度や、実際の会話遅延の測定値ではありません。

## 保存・再登録・削除

- 登録WAVと特徴：`data/speaker/profiles/<UUID>/`
- 使用中の登録ID：`data/speaker/active.json`
- モデル：`data/speaker/models/wespeaker_en_voxceleb_resnet34.onnx`
- 診断結果：`data/voice_diagnostics/<UUID>.json`の`speaker_result`と集計

会話中の比較音声はファイル保存せず、登録データの自動更新もしません。
`data/`は既存のGit除外対象です。
再登録は「新しい登録を作る」で別に行い、8本揃ってから使用する登録を切り替えます。
古い登録は自動削除しません。削除は登録を選択し「選択した登録を削除」で確認します。
その登録のWAVと特徴、使用中ならその指定を削除します。他の登録・診断レポート・会話履歴・モデルは残ります。
診断ログに残った登録ID・類似度は別途残ります。

## 開発者向け

既存のsherpa-onnx・NumPy・SciPyを使用し、新しいPython依存はありません。
モデル再準備：`.venv\Scripts\python.exe scripts/prepare_speaker_model.py`
公開モデル取得時だけ外部通信し、固定SHA-256一致後に配置します。音声は送信しません。
APIは`/speaker/status`、`/speaker/profiles`、`/speaker/profiles/{id}/samples/{prompt}`、
`/speaker/profiles/{id}/activate`、`DELETE /speaker/profiles/{id}`、`/speaker/compare`。
入力はmono PCM16 WAV、16/24/32/44.1/48kHz、最大16秒・1.6MBです。
ローカル利用を前提とし、別Originからのブラウザー書き込みを拒否します。
モデル出典・ライセンスは[third-party-notices.md](third-party-notices.md)を参照してください。

## 次の段階

### v1.51：発話単位の評価

応答・割り込み・起動語の条件と照合しきい値は変更していません。再登録は不要です。
Tray・Window・バックエンドを再起動し、使用中の登録を確認して観測照合をオンにします。
「音声診断」を開始し、条件と試行を選んでから発話してください。

- 発話一覧には診断開始からの秒数、試行番号、条件、仮判定、類似度が出ます。
  各発話で「本人／動画／両方が重なった／不明・未指定」を選択してください。
  本文は一覧には表示しません。本文のログ保存は引き続き任意です。
- 話者ラベルと「正しく応答した」などの結果の印は別です。
  誰の声か分からない発話は「不明」のままにし、推測で本人・動画を付けないでください。
- ラベルは診断中に修正でき、最後の指定を評価に使います。終了前に入力してください。
  発話検出がなかった場合は一覧に出ないため、従来の「拾わなかった」で記録します。
- 静かな本人、動画のみ、動画＋本人、短い呼びかけを比較します。
  各条件の発話を複数回試し、動画は異なる話者も含めてください。
  最後の照合結果とラベルを確認して「終了／保存再試行」で保存します。
- 登録画面に例文同士の類似度の最小値と平均値を表示します。
  ばらつき確認用であり、登録の品質・本人性の合否判定ではありません。登録データは変更しません。

材料不足でも取得できた音声長・有音区間・音割れ率を記録します。切り出しの確認用に
ブラウザー側のサンプル開始／終了位置・レート・通知受信時刻、サーバーの音声開始／終了時刻、
品質チェック後の前後トリミング位置を記録します。ブラウザーとサーバーは異なる時計です。
これらだけでは実際の発話開始との正確な一致は証明できません。切り出し方法自体は維持します。

読み取り専用評価（出力は標準出力、設定やログを書き換えません）：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_speaker_diagnostics.py data/voice_diagnostics/<ID>.json --thresholds 0.60 0.80 0.85 0.90 0.95
```

明示された本人・動画ラベルだけで誤拒否数／動画通過数と分母を比較します。
混在・不明・未計測は別集計です。旧ログから測定条件を根拠に話者を推測しません。
数値は測定データ内の比較であり、実運用のしきい値を自動決定するものではありません。
別の動画・別の測定回でも確認してから応答制御へ進みます。

今回は登録・観測・診断補強までです。本人判定の有効化は測定結果の確認後です。
既存の「受付判定より先に応答を要求する」動作もまだ変更していません。
本人判定を応答に適用する際に、この順序と、拒否した入力を会話へ残さない処理も修正します。
対象話者抽出、相手への呼びかけかの判定、音声でのOffは未実装です。
実機では録音とWake Wordの競合、録音後の再接続、マイク・スピーカー、照合オフ時の動作、
Windowを閉じた後のTray復帰も確認してください。
