# 会話中の音声診断（v1.49）

## 目的と変更しない範囲

本人の声の聞き逃し、動画への誤応答、応答待ち時間の現状測定用です。
起動語、VAD、文字起こしモデル・言語、受付／割り込み条件は変更しません。
診断は初期状態では無効です。v1.50では[本人の声の登録・観測用照合](speaker-observation.md)を
追加しました。照合も初期状態では無効で、会話の許可／拒否には使用しません。

v1.50では手動の印に対象試行番号を指定でき、遅れた結果も元の試行へ記録できます。
応答要求時の処理状態と、許可リストに含まれるエラーコードも保存します。
照合を有効にすると、`speaker_result`に類似度、仮判定、計算時間、ローカル通信込みの時間、
音声長、有音区間長、発話開始検出時にJarvisが出力中だったかを追加します。
`report.speaker_observations`は観測結果の集計で、本人／他人の正解率ではありません。

## 実機測定手順（ユーザーの作業）

v1.51では発話一覧で話者を指定できます。`speaker_label`イベントをsessionとitemの組で
対応付け、最後の指定を`report.turns`と`report.speaker_observations.results`に反映します。
`owner/video/mixed/unknown`を使用し、測定条件や応答の印から話者を自動補完しません。
診断終了前にラベルを入力してください。詳細は[speaker-observation.md](speaker-observation.md)を参照してください。

1. TrayとWindowを完全終了し、通常の方法でJarvisを再起動します。
   保存APIも追加するため、バックエンドが古いままにならないようにします。
2. 画面右上の「音声診断」を開き、「診断開始」を押します。
   文字起こし本文の追加保存は任意です（初期状態はオフ）。
   既存の会話履歴の保存動作は変わりません。
3. 音声接続が準備完了してからテストします。診断開始自体はマイクを起動しません。
4. 条件を選び、毎回「次の試行」を押してから発話します。
   返答を待ち、結果を印付けしてから次の試行へ進んでください。
   発話中や文字起こし待ちに次の試行へ進むと、手動印との対応が曖昧になります。
5. 「終了／保存再試行」を押し、「保存完了」を確認します。
   ファイル名を伝えていただければログを分析できます。

最初は10〜15分を目安に、以下を実施します。

| 条件 | 試行内容 |
| --- | --- |
| 静かな環境 | 「元気？」「今日は何日？」「短い物語を二文で話してください」「ありがとう」を各2回 |
| 動画だけ | 別端末の普段誤反応する動画を1試行60秒×3回再生。本人は話さない。誤応答ごとに「他の音に反応した」 |
| 動画＋自分の声 | 同じ動画音量・マイク位置で、静かな環境と同じ4発話を各2回 |
| Jarvisに割り込む | 少し長い返答を頼み、その途中で「ジャービス、止めて」を3回別々に試す |

結果の印は「正しく応答した」「今の発話を拾わなかった」「他の音に反応した」「不明」です。
未記入・矛盾する印は成功に数えません。「正しく応答した」は文字起こしが出ただけでなく、
意図に合った返答があった場合です。予定発話から変更した場合は試行番号と内容を別途伝えてください。
開始時と最後にスピーカー出力を確認し、最後に音声切断→再接続、Window閉じる→再表示、
Trayから起動語待ちに戻れることも確認してください。

## 保存とプライバシー

- 保存先：`data/voice_diagnostics/<診断UUID>.json`。ログと集計レポートを一緒に保存します。
- 診断中は5秒ごとと印付け時、終了時に保存します。保存はファイル単位で置き換えます。
- 生音声、SDP、APIキー、APIエラー本文、デバイスIDは保存しません。
  入力デバイス名、取得可能なサンプルレート／チャンネル数／音声処理設定、ミュート状態は保存します。
- 文字起こし本文は明示的に選んだ場合だけ、1イベント最大2000文字を診断ログに保存します。
- 新しい外部送信先は追加しません。既存のRealtime音声通信は従来どおりです。
- ファイルは自動削除しません。`data/`は既存のGit除外対象です。
- 保存失敗時はウィンドウを閉じずに再試行してください。
  強制終了・ウィンドウ閉鎖時には最後の未保存分を失う場合があります。
  途中保存の`complete: false`は正常終了した測定として扱いません。
- 約3MBの保守的な推定容量、9998イベントまたは23時間を超えると診断を自動終了します。
  会話自体は終了しません。追加測定は新しい診断で行います。

## 集計の意味と限界

処理順は「発話検出→終了検出→文字起こし／応答要求→音声出力開始」を記録します。
現在の会話処理では、通常発話の終了検出で応答を要求するため、文字起こしより先になる場合があります。
負の`transcript_to_request`をゼロに補正せず残します。

`report.metrics`は件数・平均・p95（nearest rank）をミリ秒で集計します。
`stop_to_audio`は終了検出イベント受信から音声出力開始イベント受信までです。
VADが無音を待つ時間、実際のスピーカー出力遅延は含めて正確には測れません。
録音しないため、声を出した真の時刻や、検出されなかった音声内容も自動判定できません。

発話はsession IDとitem IDで識別します。遅れて来る文字起こしは発話開始時の試行番号を維持します。
応答はresponse IDを追跡しますが、要求との対応は「未処理要求が1つだけ」の場合に限った推定です。
複数の応答要求が重なる場合は対応付けず、その遅延サンプルを除外します。
起動挨拶・テキスト・tool応答は本人の発話遅延に混ぜません。

`manual_by_scenario.reported_success_rate`は、ユーザーが結果を付けた発話のうち
「正しく応答した／（正しく応答した＋拾わなかった）」です。自動的な話者精度ではありません。
動画の誤反応は手動の印の件数で、重複クリックは重複して数えます。レポートの試行一覧で確認します。
未記入・不明・矛盾した印は別に残します。拒否された発話でも、それ以前に応答要求が送られている
場合があるため、`accepted/rejected`だけで応答したかを判定しないでください。

## 実装境界

`static/js/audio/voice-diagnostics.js`は観測専用です。Realtimeへのイベントを送信せず、
観測関数の例外は会話処理へ伝えません。`static/script.js`は観測フックとローカルの
応答要求識別情報のみ追加し、モデルへ送信する応答要求本体は変更していません。
`app/routes/voice_diagnostics.py`はサイズ・型・保存先を制限し、本文保存の選択を再検証します。
APIはローカル利用を前提とし、ブラウザーの別Originからの保存を拒否します。

実機のマイク、スピーカー、騒音下の精度は自動テストでは検証できません。
